# 12.11 小结

本节把前三章的许多材料串成一体，办法是描述套接字层和网络层在正常使用中的运作。

套接字的一生有三个阶段：初建——创建套接字并与某个通信域关联；存活——数据经它流往一个或多个其他套接字；终结——不再需要时，经过有序的关闭过程释放资源。

**创建通信信道**

套接字由用户用 `socket` 系统调用创建，内部经 `socreate()` 例程。创建套接字时，用户须给出通信域和套接字类型，还可以请求域内的具体通信协议。套接字例程先从引导时为每个配置域初始化的全局列表中定位通信域的 `domain` 结构；域结构中找到构成该域协议族的协议表；然后扫描这张协议开关表项的表，为所创建套接字的类型（或指定的具体协议）找合适的协议。套接字例程靠检查 `pr_type` 字段（含可能的套接字类型，如 SOCK_STREAM）和 `pr_protocol` 字段（含协议的协议号，通常是著名值）完成搜索。找到合适的协议，对它协议开关表项的引用就记入套接字的 `so_proto` 字段，此后一切网络服务请求都经结构中标识的相应过程进行。

定位到协议的句柄后，`socreate()` 分配一个 mbuf、以套接字的初始状态创建套接字数据结构。为完成创建，`socreate()` 向协议的用户请求例程发 PRU_ATTACH 请求，让协议把自己 **附接** 到新套接字上。

接着可以把地址绑定到套接字。地址的绑定内部由 `sobind()` 完成，它向套接字的支撑协议发 PRU_BIND 请求。Internet 和 XNS 域各有一个管理自己地址空间的例程。UNIX 域的地址是文件系统名字空间中的名字，名字请求因此要经文件系统的名字查找例程 `namei()`。

套接字要准备接受连接，套接字层必须以 PRU_LISTEN 请求告知协议。这一请求对 UDP 和 IDP 等无连接协议显然无意义；对 TCP 和 SPP 等面向连接的协议，listen 请求则引起协议状态转换。状态转换前，协议核实套接字已绑定地址；没有，协议模块替它选一个。

UNIX 域中 listen 请求不引起状态变化，只检查套接字有名字；但与其他协议不同，UNIX 域不替套接字选名字。

`soconnect()` 被调来建立连接，向协议发 PRU_CONNECT 请求。无连接协议把地址记为默认地址，供套接字上发送数据时使用（即进程做 `write` 或 `send` 而不是 `sendto`）；设置地址无须任何对端通信，协议模块立即返回。

基于连接的协议则验证对端地址，为未绑定的套接字指派本地地址。套接字不立即进入 **已连接** 状态，而是经 `soisconnecting()` 标记为 **连接中**；协议随即发送连接请求消息与对端握手。这种连接请求完成时——通常在协议输入例程收到消息之际——套接字的状态经调用 `soisconnected()` 改变。

在用户看来所有连接请求都是同步的：`connect` 系统调用调用 `soconnect()` 发起连接，然后在套接字层把调用进程入睡（若连接请求尚未完成）。或者，套接字已经 `fcntl` 成非阻塞时，连接一经成功发起 `connect` 就返回 EINPROGRESS 错误；调用者可以用 `select` 测试能否写套接字来检验连接的完成。

基于连接的通信中，进程必须在监听套接字上调用 `accept` 接受入局连接请求，后者转而调用 `soaccept()`，从套接字接收队列返回下一个已完成的连接。

**收发数据**

套接字一经创建，数据就可以开始流经它。一条典型的 TCP/IP 连接见图 12.10。`sosend()` 例程负责把数据从发送进程的地址空间复制进 mbuf，然后以一次或多次对协议 PRU_SEND 请求的调用把数据呈交网络层。网络可以选择立即发送数据或等更好的时机；协议若推迟、或必须保留数据副本以备重传，可以把数据存在套接字的发送缓冲。最终，数据经 TCP 和 IP 向下传给适当的接口驱动程序，成为一个或多个分组；每层都加上相应的头部。每个分组经网络发往目的机器。

![图 12.10 TCP/IP 连接经以太网的数据流（ETHER 为以太网头；PIP 为伪 IP 头；IP 为 IP 头；TCP 为 TCP 头）](../.gitbook/assets/fig-12-10-figure-12-10-data.png)

目的机器收到时，接口驱动的接收中断处理程序校验并剥掉自己的头部，把分组放上适当的网络协议输入队列。稍后，网络级输入处理模块（如 IP 或 IDP）被软件中断唤起；它运行的中断优先级低于硬件网络接口中断。本例中，输入队列上的分组先由 IP 再由 TCP 处理，各自校验并剥掉自己的头部。按序收到的话，数据随即放到适当套接字的输入队列上，等 `read` 请求到来时由 `soreceive()` 复制出去。

**终止数据传输和/或接收**

`soshutdown()` 例程停住套接字处的数据流。关闭套接字的读取很简单：冲掉接收队列并标记套接字不能再收数据——调用 `sorflush()`，它转而调用 `socantrcvmore()` 改变套接字状态，然后释放接收队列关联的资源。关闭套接字的写入则要经 PRU_SHUTDOWN 请求通知协议。可靠连接的发送队列中若仍有数据，必须排空后连接才能完成关闭。协议若支持 **半打开** 连接（即允许单向数据流的连接），套接字可以继续使用；否则协议可以开始断开序列。套接字两个方向都关闭后，协议开始断开序列；断开完成时，先释放网络关联的资源，再释放套接字关联的资源。
