# 11.3 协议-协议接口

协议模块之间的接口使用 `pr_usrreq()`、`pr_input()`、`pr_output()`、`pr_ctlinput()` 和 `pr_ctloutput()` 例程。`pr_usrreq()` 和 `pr_ctloutput()` 供套接字层与协议通信，调用约定是标准的；其余例程通常不在协议族之外访问，因而演化出各异的调用约定。

理论上为协议的所有入口点强加标准调用约定或许能允许协议模块任意互联，实践上却非常困难：跨越协议族边界需要把网络地址从调用方域的格式转换成被调方域的格式。因此，不同通信域之间协议的连接一般不受支持，前段所列例程的调用约定通常按域标准化。

下面几小节简述协议的一般框架和调用约定。第 12 章考察具体协议如何嵌入这一框架。

**pr_output**

协议输出例程常用为在一条连接上发送单条消息而设计的调用约定，例如：

```c
error = (*pr_output)(pcb, m);
    struct pcb *pcb;
    struct mbuf *m;
```

较低层协议的输出例程不一定总有协议控制块，可能需要更显式的参数。

**pr_input**

上层协议的输入例程通常在网络层协议找到协议标识符之后于软件中断级被调用。它们一般比输出例程更程式化，因为常经协议开关调用。视协议族性质，它们可能收到标识连接的控制块指针，也可能得从收到分组的信息中定位控制块。典型的调用约定是：

```c
(void) (*pr_input)(m, ifp);
    struct mbuf *m;
    struct ifnet *ifp;
```

本例中，收到分组的接口作为第二参数传递，由协议做连接级的多路分解。

**pr_ctlinput**

这一例程用来把 **控制** 信息（可能传给用户、但不属于数据的信息）从一个协议模块向 **上** 传给另一个。常用调用约定是：

```c
(void) (*pr_ctlinput)(req, addr);
    int req;
    struct sockaddr *addr;
```

`req` 参数取表 11.4 所列值之一，`addr` 参数是条件适用的地址。许多请求源自网际控制报文协议（ICMP）[Postel, 1981] 和 1822 主机/IMP 约定中定义的错误报文 [BBN, 1978]。

表 11.4 控制输入例程的请求

| 请求 | 描述 |
| ---- | ---- |
| PRC_IFDOWN | 网络接口变迁 |
| PRC_ROUTEDEAD | 尽可能另选路由 |
| PRC_MSGSIZE | 消息大小迫使分组被丢弃 |
| PRC_HOSTDEAD | 远程主机关机 |
| PRC_HOSTUNREACH | 远程主机不可达 |
| PRC_UNREACH_NET | 无到网络的路由 |
| PRC_UNREACH_HOST | 无到主机的路由 |
| PRC_UNREACH_PROTOCOL | 目的地不支持该协议 |
| PRC_UNREACH_PORT | 目的地端口号未使用 |
| PRC_UNREACH_NEEDFRAG | 需要分片但不允许 |
| PRC_UNREACH_SRCFAIL | 源路由失败 |
| PRC_REDIRECT_NET | 网络的路由重定向 |
| PRC_REDIRECT_HOST | 主机的路由重定向 |
| PRC_REDIRECT_TOSNET | 按服务类型与网络的路由重定向 |
| PRC_REDIRECT_TOSHOST | 按服务类型与主机的路由重定向 |
| PRC_TIMXCEED_INTRANS | 分组寿命在传输中耗尽 |
| PRC_TIMXCEED_REASS | 寿命在重组队列中耗尽 |
| PRC_PARAMPROB | 检测到头部参数问题 |
